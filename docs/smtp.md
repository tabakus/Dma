# SMTP-интеграция: требования и план проверки

Провайдер, адрес получателя и реквизиты **не утверждены**. В коде и конфигурации их нет.

## Почему собственный SMTP-клиент

Cloudflare Pages Functions работают в Workers Runtime, а не в Node.js. Nodemailer и большинство
Node.js SMTP-библиотек используют модули `net`/`tls`, которых там нет. Режим `nodejs_compat`
даёт только часть Node API, и совместимость таких библиотек не гарантирована, поэтому
на них не опираемся.

Решение: небольшой клиент `server/smtp/client.ts` на стандартных Web API (TextEncoder, btoa)
и TCP/TLS-сокетах Cloudflare (`connect()` из `cloudflare:sockets`, адаптер
`server/smtp/cloudflare-socket.ts`). Протокол покрыт тестами на имитации SMTP-сервера
(`tests/smtp.test.ts`). Сборка функции проверена: из внешних модулей импортируется только
`cloudflare:sockets`, модулей Node.js в бандле нет.

Альтернатива для обсуждения: npm-пакет `worker-mailer`, написанный под `cloudflare:sockets`.
Он не подключён: свой клиент проще проверить построчно, и он не добавляет зависимость.

## Требования к провайдеру

| Требование | Почему |
| --- | --- |
| SMTP с аутентификацией (AUTH PLAIN или AUTH LOGIN) | Клиент поддерживает эти два механизма |
| Порт **465** (TLS с первого байта) или **587** (STARTTLS) | Порт 25 в Cloudflare закрыт и не используется |
| Сертификат TLS, выданный публичным центром сертификации | Сокеты Cloudflare проверяют сертификат |
| Пароль приложения / отдельный SMTP-пароль | Не использовать основной пароль ящика |
| Ящик отправителя на домене сайта, SPF/DKIM/DMARC настроены | Иначе письма попадут в спам |
| Сервер в ЕС и договор обработки данных (AVV/DPA) | DSGVO: в письме персональные данные |
| Не блокирует подключения из IP-диапазонов Cloudflare | Некоторые провайдеры ограничивают облачные IP |

Не поддерживается сейчас (и не требуется по ТЗ): OAuth2 (XOAUTH2), несколько получателей,
вложения, HTML-письма, автоответ посетителю.

## Переменные

`SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURITY` (`tls` | `starttls`), `SMTP_USERNAME`,
`SMTP_PASSWORD` (**Secret**), `MAIL_FROM`, `MAIL_TO`, `ALLOWED_ORIGINS`. Описание — в README.
Сочетание порта и режима проверяется: 465 + `tls` или 587 + `starttls`, иначе `not_configured`.

## План проверки после выбора провайдера

Не выполнен — нет провайдера и реквизитов.

1. Создать тестовый ящик / пароль приложения у выбранного провайдера.
2. Локально: `.dev.vars` с реквизитами → `npm run build` → `npx wrangler pages dev dist`
   → отправить форму на тестовой странице продукта. Ожидается письмо и ответ `{ ok: true }`.
3. Проверить оба режима, если провайдер их поддерживает (465/`tls` и 587/`starttls`).
4. Негативные проверки: неверный пароль → ответ 502 `delivery_failed`, в логах Cloudflare
   только `{"event":"delivery_failed","stage":"auth","code":"535"}` без персональных данных.
5. Preview-деплой Cloudflare Pages с переменными Preview → та же проверка уже в Cloudflare
   (подтверждает работу `cloudflare:sockets` с этим провайдером).
6. Проверить доставку: письмо не в спаме, корректная кириллица/умлауты в теме и теле, Reply-To
   ведёт на адрес посетителя.
7. Задокументировать результат здесь и закрыть вопрос в `docs/open-questions.md`.
