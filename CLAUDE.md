# CLAUDE.md — правила работы с проектом Deutsch mit Akzent

Сайт авторской онлайн-школы немецкого языка. Статический сайт на Astro + серверная обработка
заявок в Cloudflare Pages Functions с отправкой по SMTP. Админ-панели и базы данных нет.

- Репозиторий: https://github.com/tabakus/dma, основная ветка `main`.
- Язык первой версии сайта — русский (`locale: ru`). Другие языковые версии сейчас не делаются.
- Стек и архитектура утверждены заказчиком (см. «Принятые решения» в `docs/open-questions.md`);
  не предлагай альтернатив и не выноси их в открытые вопросы.

**Текущий этап:** технический каркас; бренд-система v2.0 «Старинная библиотека» (цвета, шрифты, фото; логотип не изменён) внесена в токены
(`docs/brand-system.md`). Дизайн страниц и тексты — отдельные будущие задачи.
Не переходи к ним без отдельного задания владельца. Репозиторий подключён к Cloudflare Pages
(`https://deutschmitakzent.pages.dev`, технический каркас; домен не подключён); отправка заявок не настроена.

## Главные правила

1. **При обычном обновлении курса или семинара меняй только файлы контента** этого продукта
   (`src/content/courses/<папка>/`, `src/content/seminars/<папка>/`). Компоненты, схемы,
   маршруты и серверный код при этом не трогаются.
2. **Не переписывай авторские тексты** без отдельного разрешения. Исправление явной опечатки —
   только с пометкой в отчёте.
3. **Не придумывай** цены, даты, условия, уровни, продолжительность, отзывы, реквизиты.
   Нет данных → поле не заполняется (удаляется из frontmatter), а владельцу сообщается, чего не хватает.
4. **Не меняй утверждённую архитектуру** (структуру папок, схемы, маршруты, контракт формы, способ
   отправки заявок) самостоятельно. Сначала объясни владельцу причину и получи согласие.
5. **Никаких секретов в репозитории**: SMTP-пароль и реквизиты только в переменных Cloudflare
   или в локальном `.dev.vars` (в `.gitignore`).
6. **Юридические тексты** (Impressum, Datenschutzerklärung, текст согласия) не пишешь. Их даёт владелец
   или специалист; ты только размещаешь готовый текст.
7. Не подключай аналитику, пиксели, cookie, внешние шрифты (Google Fonts CDN), виджеты и сторонние
   сервисы форм без решения владельца.

## Как добавить курс

1. Скопируй папку-образец `src/content/courses/_example-course/` в новую папку **без** `_` в начале.
   Имя папки = адрес страницы: латиница в нижнем регистре, цифры, дефисы (`grammatik-b1` → `/kurse/grammatik-b1/`).
2. Заполни frontmatter **только реальными данными владельца**. Всегда обязательны: `title`, `status`,
   `direction` (`grammatik` | `beruf`). Для публикации (`status: published`) ещё обязательны `level`, `format`,
   `duration`, `summary`. Необязательные: `titleDe`, `order`, `start`, `end` (только вместе со `start` и не раньше него),
   `schedule` (дни и время словами), `groupSize` (максимум человек), `price` (евро), `currency` (только `EUR`),
   `cover` + `coverAlt`, `seo`. План курса — раздел в тексте `index.md`.
3. Текст страницы — в теле `index.md` (Markdown), без HTML и без встроенных скриптов.
4. Изображение-обложку положи в ту же папку и укажи `cover: ./cover.jpg` и `coverAlt`.
5. Статусы: `draft` — черновик, на сайте не виден; `announced` — анонс: название видно в списках с пометкой
   «Скоро», страницы и заявки нет; `published` — своя страница (описание, план, стоимость, форма заявки);
   `archived` — снят. `published` — только по решению владельца и когда есть все данные.
6. Запусти `npm run verify`.

## Как добавить семинар

То же самое в `src/content/seminars/` по образцу `_example-seminar/`. Всегда обязательны: `title`, `status`,
`direction`; для публикации ещё `format`, `summary`. Необязательные: `titleDe`, `level`, `duration`, `schedule`, `groupSize`, `start`, `end`
(только вместе со `start` и не раньше него), `price`, `order`, `cover` + `coverAlt`, `seo`.

## Подразделы обучения

- Подразделы — `src/data/directions.yaml` (ключ = значение `direction`), страницы — `/deutsche-grammatik/`,
  `/berufseinstieg/` (общий шаблон `src/components/learning/DirectionPage.astro`).
- В шапке каждого подраздела — заметная ссылка на пробный видеоурок. Пока `video.href: null`, это муляж,
  ведущий к месту видео на странице (`#probeurok`). Готовое видео — ссылка `https://` на площадку; встраивание
  плеера — только после решения по DSGVO.
- Подраздел со `status: preparing` показывает «Программа в подготовке».
- Курсы и семинары на странице подраздела и в каталогах — матовые мини-блоки (`src/components/catalog/ProductTile.astro`):
  название сначала по-немецки, под ним по-русски; уровень, продолжительность, группа, старт. Клик по опубликованному открывает страницу продукта
  (`src/components/product/ProductPage.astro`: описание, стоимость, условия, форма заявки).
- В меню и в ссылках главной подразделы называются «Грамматика» и «Старт карьеры»; каталоги `/kurse/`, `/seminare/`
  остаются, но в меню не выводятся.

## Изменение и снятие с публикации

- Правка цены, даты, текста — только в `index.md` этого продукта.
- Снять с публикации: `status: archived` (или `draft`). Страница и карточка исчезнут из сборки,
  форма перестанет принимать заявки на этот продукт. **Папку не удалять** без отдельного решения владельца.
- Папки с `_` в начале — образцы: проверяются схемой, на сайт не попадают. Не удалять.

## Схемы данных

- Схемы — в `src/lib/schemas.ts`, подключение — в `src/content.config.ts`.
- Объекты строгие: опечатка в имени поля (`tilte`) — ошибка сборки. Это защита, не обходить её.
- Ошибка сборки из-за схемы → исправляй **данные**, а не схему.
- Новое поле, изменение обязательности или допустимых значений — изменение архитектуры (правило 4):
  обнови схему, тесты (`tests/schemas.test.ts`), образцы `_example-*`, этот файл и `README.md`.

## Компоненты и стили

- Компоненты получают данные через props и не содержат текстов продуктов.
- Цвета, шрифты, отступы — только через переменные из `src/styles/tokens.css` (бренд-система v2.0,
  `docs/brand-system.md`). Сайт тёмный; светлый блок — класс `.paper`. Текст поверх фото — только на затемнении
  или матовом стекле. Золото `#C9A45C` мелким текстом на стекле запрещено. Новые цвета не добавлять без решения владельца; белый текст на розовом и розовые
  ссылки на светлом фоне запрещены (недостаточный контраст).
- Логотип подключается только через `src/components/brand/Logo.astro` (`variant="light" | "dark"`);
  исходники SVG — `src/assets/brand/`, не изменять.
- Шрифты — Literata (заголовки) и Inter (текст), вариативные, только локально в `public/fonts/` (DSGVO).
- Фоновые фото — `src/assets/library/`, только через `src/components/brand/PhotoBackdrop.astro`.
- JavaScript — только для интерактивности (сейчас: форма заявки и мобильное меню). Без клиентских фреймворков.

## Главная страница

- Тексты — только в `src/data/home.yaml`; секции — `src/components/home/Home*.astro`, сборка — `src/pages/index.astro`.
- Необязательная секция не выводится, если её нет в `home.yaml`. Фрагмент в `[[двойных скобках]]` выделяется
  фирменным цветом (только в крупных заголовках).
- Комментарии `[материалы]` / `[предложение]` в `home.yaml` показывают происхождение текста; предложения
  меняются только по решению владельца.
- Автор: имя, текст и ссылка выводятся, только если заданы; без фото показывается место для фотографии.
  Фото и биографию не придумывать.
- Ссылки в YAML — только внутренние: `/kurse/` или якорь `/#obuchenie`. Якоря главной: `#obuchenie`, `#avtor`.

## Требования

**Адаптивность:** вёрстка от 320 px; гибкие сетки (CSS Grid/Flex), относительные единицы;
без горизонтальной прокрутки страницы; формы удобны на телефоне (типы полей `email`, `tel`, `autocomplete`).

**Производительность:** страницы без JS по умолчанию; изображения через `astro:assets`
(обложки из `cover`; сейчас они используются только для Open Graph, вывод на страницах — этап дизайна);
шрифты WOFF2 с `font-display: swap`; анимации — CSS, с учётом `prefers-reduced-motion`.

**Доступность:** семантические заголовки по порядку, подписи у всех полей, видимый фокус,
`alt`/`coverAlt` для изображений, контраст текста не ниже WCAG AA.

**SEO:** у каждой страницы свой `title` и `description` (для продуктов — `seo` или `title`/`summary`);
canonical, Open Graph, sitemap и robots.txt генерируются автоматически.

**Безопасность:**
- секреты только в переменных Cloudflare (`SMTP_PASSWORD` — тип Secret);
- сервер проверяет все поля заново, браузерной проверке не доверяет;
- в логи не пишутся имена, адреса, телефоны и тексты заявок;
- данные посетителя в письме — только в теле или в закодированных заголовках (см. `server/application/email.ts`);
- сообщение об успехе — только после того, как SMTP-сервер принял письмо;
- ограничение частоты и серверная защита от повторной отправки работают только с KV `APPLICATION_KV`,
  которое **не подключено**; не описывай их как действующую защиту (вопрос В-5 в `docs/open-questions.md`);
- SMTP-клиент проверен только на имитации сервера; не называй интеграцию готовой (см. `docs/smtp.md`);
- CSP генерирует Astro (`security.csp`); не добавляй inline-обработчики (`onclick=`) и `javascript:`-ссылки.

## Проверка перед публикацией

```bash
npm run verify   # astro check + проверка типов сервера + тесты + сборка
```

Все шаги должны пройти без ошибок. Затем изменения идут в отдельной ветке → Pull Request →
preview-деплой Cloudflare Pages →
проверка владельцем → слияние в `main` → публикация. Напрямую в `main` не отправлять.
Откат — возврат к предыдущему деплою в Cloudflare Pages или revert коммита.
